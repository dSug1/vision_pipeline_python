## Appended 2026-08-25 — ⚠⚠ RE-OPENED AND WIDENED by rule 3's removal

`F1` removed the **thumb-outward snap restriction** (owner request: an object may
be grabbed with the back of the hand to the camera, including on re-entry). Rule 3
had been suppressing part of this row **incidentally** — a back-of-hand hand was
refused a snap, which happens to be the pose a stealing hand presents.

⭐ **Measured from the six takes whose recordings carry the rule's own fields**
(3432 hand-frames): rule 3 refused on **15.7%** of hand-frames, and on **8.3%**
the hand held nothing — i.e. a grab that is now allowed. Some fraction of those
8.3% are steals.

⛔ **Do NOT answer this by reinstating a facing gate.** That gate was removed on
evidence, not on preference: it read `is_thumb_outward`, which is
handedness-dependent and **inverts on a wrong label** (wrong 10.8% of the time
until `U7`). Re-adding it would restore a rule that fires on the wrong hand a
tenth of the time.

⭐ **The fix stays where it already was routed**: `B5` (grab from the finger arcs)
with `4.4` (hand-open release) — one project. A steal is only possible because
*holding* is inferred from proximity rather than from the hand actually being
closed. `F1`'s fingertip work is the same mechanism from the third side.
